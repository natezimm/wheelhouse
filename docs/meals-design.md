# Weekly meal plan (6.1)

Phone /meals shows seven stacked day cards; wall /wall/meals uses seven columns. Every day shows Breakfast, Lunch and Dinner, including empty slots. Week navigation respects the family's week-start preference and dates are plain household-local dates. Phone Today has a separate planned-meals card and a link to the week. Meals never become Google events.

Tap a slot to edit its title (200 characters) and notes (2000). Clear is a separate confirmation, never an empty accidental save. Normal, empty and loading slots have explicit labels. Saving slots show pending intent over confirmed data. Definite failures restore accepted contents and retain the editor draft; uncertain replies freeze the command with Check save. Reconnection/live reads do not alter the viewed week, open draft or copy selections. Family changes discard all old state. Targets are at least 44px on phone and 56px on wall.

Copy previous week is phone-only. It reads a source snapshot and lists each populated source slot, its destination and any existing meal. Empty destinations are selected by default; occupied destinations require an explicit overwrite selection. Empty source slots never clear destinations. Submitting copies only the reviewed selections atomically, leaving the source unchanged. Source and destination versions are checked; a change to either refuses the whole batch. Review latest reloads the preview and choices explicitly.

MealSlot has a unique family/date/slot key and opaque version. Clearing retains an empty versioned row so an older empty-slot editor cannot overwrite a later fill-and-clear (ABA). Reads project all three slots without writing missing rows. A missing row has a null version. PUT slot and POST copy commands carry immutable operation IDs. Family-owned command receipts record successful normalized requests atomically; retries return current state without reapplying even after another edit. Changed-body ID reuse conflicts. Commands serialize with a family advisory lock. No-op commands/receipts do not advance the meals revision.

Snapshots read a 1–14 day exclusive-end range with the durable MealsChangeNumber in repeatable-read isolation. SaveChanges increments the meals counter once per affected family in the same transaction. HouseholdChanged gains an independent meals domain with the existing authorization/revocation rules. The client rejects stale range replies and retains original ranges/commands for recovery after navigation.

Demo seeding includes breakfast, lunch, dinner, notes, empty slots and a previous week for copying. New private families start empty; family deletion cascades slots and receipts. PostgreSQL API tests and mocked-transport browser checks validate isolation, concurrency, copy choices, dates, cleanup and recovery. Recipes and grocery generation remain 6.2/6.3.
