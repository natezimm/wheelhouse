# Shared checklists (5.1)

Phone `/lists` and wall `/wall/lists` share a screen using existing color and typography tokens. A named-list selector and New list action lead into a card with the selected name, rename/archive actions, a quick-add text field, remaining items and a collapsed checked section. Each row has check/reopen, edit, move up/down and an explicit Delete action. Ordering controls operate within the row's checked/unchecked section. Archiving requires confirmation and keeps items; an Archived lists view makes preserved contents readable. Archived lists are read-only. Nothing here adds grocery categories or quantities.

Normal: show remaining count and notes. Empty: invite a new list or first item. Loading: keep controls unavailable until the first snapshot. Saving: show pending feedback and freeze that list's controls while retaining text. Failed: preserve draft, remove only a refused overlay and explain conflict; the user reviews current state before retry. Uncertain: keep the frozen command and expose Check save globally, even if its editor is closed. Reconnecting: retain accepted contents and drafts; Resync now reloads the server snapshot. Switching lists never clears a draft. Family changes clear contents and drafts.

All authenticated family clients, including paired walls, manage lists. Every mutation uses a family transaction lock. Creates carry immutable operation IDs and normalized request fingerprints. Items use explicit checked booleans and versions. Reordering checks the reviewed list version and swaps two deterministic positions; concurrent additions append without replacing a collection. Deletes keep an internal tombstone to reconcile lost replies and create retries. Archived lists retain their items. Snapshot data and `Family.ListsChangeNumber` use one repeatable-read transaction. Household notifications add the `lists` domain alongside chores. No third socket or upstream sync.

Wall controls are at least 56px; phone controls 44px. Forms use visible labels and native dialogs, keyboard buttons and move actions rather than drag-only gestures. Browser validation uses mocked API and SignalR transports at 1920×1080 and 390×844 and must be described as such.
